# Data Quality Report

Generated by `analysis/01_profile.py` on 2026-09-28 from the local raw copy (`data/raw/`). Regenerate with `make profile`. Detail files (per-column stats, monthly volumes and null rates, lag histograms, value counts) are written to `analysis/out/profile/<table>/` (git-ignored).

- Source: organizer-provided **synthetic** dataset; see [`data_inventory.md`](data_inventory.md) for files and partitions.
- Method: every column is read as text, so malformed values are counted instead of failing the load. A column's type is the first of boolean, integer, decimal, timestamp, date, date or timestamp, time that at least 99% of its non-null values parse as; the rest are reported as malformed. Null-like text (`None`, `nan`, `NULL`, `N/A`…) counts as null.
- Duplicates are counted on the raw rows; an *exact* duplicate repeats every column, a *key* duplicate repeats the primary key. Late arrival = `process_date` minus the event date, in days.
- Personal columns (names, documents, contact data, card numbers, IPs, coordinates, free text) are measured but their values are never listed.

## What this means for the ETL

Rules the raw → silver pipeline (`etl/pipeline/`) takes from the findings above:

1. **Business dates come from the event timestamp**, never from `process_date` or the partition folder (processing-day cut-off, survey dating). `process_date` is only the load watermark.
2. **Deduplicate by primary key, keeping the row with the latest `process_date`**, and check content duplicates under a new key, even though this copy has none: the organizer announced both.
3. **Load incrementally by partition/`process_date`** and re-run on every re-sync; a test fixture delivers a record late (a newer version of an existing key) and must update it without duplicating.
4. **Recompute `amount_usd`** as `amount × rate(transaction date)` from `daily_exchange_rates` (USD rows: the amount itself) and keep the shipped value as `amount_usd_source` for audit; flag rows without a rate for that day (ADR 0002).
5. **Normalize country names** (`Mexico` → `México`) in customer, branch, agent and campaign columns; in `transactions.transaction_country` derive `is_international` first, since `Mexico` there marks a foreign-country transaction.
6. **Do not enforce** `customers.registration_branch_id`, `service_agents.assigned_branch_id` as foreign keys (they almost never resolve): keep the value, add a `*_resolved` flag. Quarantine only rows whose normally-valid keys fail (every other foreign key resolves today).
7. **Null contracts per column, from the observed rates** (not a global 5%): required columns have 0% nulls today and stay required, and drifting columns (`campaign_sends.subject`, `campaign_sends.was_opened`, `campaign_sends.open_date`, `campaign_sends.open_device`, `campaign_sends.open_country`) get a tolerant bound.
8. **Keep `complaints.affected_product_id` out of joins**: it never points to the complainant's product. Complaint ↔ transaction matching uses the customer's own cards.
9. **Coordinates near (0, 0) become null** with a `coords_invalid` flag; phone prefixes are not used to infer a country.
